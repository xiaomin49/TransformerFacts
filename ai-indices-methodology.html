EAPI 企业 AI 渗透指数

EAPI（企业 AI 渗透指数）追踪企业在实际业务中引入并使用 AI 的渗透速度。 它同时纳入「新增采用」与「真实在产用量」两个维度：前者用 npm 包下载量衡量新应用接入， 后者用 OpenRouter 真实 token 成交量衡量已装机应用在持续调用 API 的存量贡献。 本页说明其编制原理，并补充「真实支出指数」——引入 token 价格代理做平减，逼近企业真实 AI 支出口径。

EAPI

Enterprise AI Penetration Index

EAPI 追踪企业在实际业务中引入并使用 AI 的渗透速度，由两个互补维度几何混合而成： ① 新增采用（flow）用 npm 包下载量衡量新应用接入（模型调用层 + 生产集成层）； ② 真实在产用量（usage）用 OpenRouter 全模型周度 token 成交量衡量已装机应用持续调用 API 的存量贡献。 后者天然包含"存量包 + 新增下载"共同产生的 Token 消耗，弥补原口径只测新增下载、低估成熟生态用量增长的短板。

编制公式
# A. 新增采用维度（flow）—— npm 包下载量（5 个活跃包）
# Step 1：归一化（各包除以基准周值，锚定 base=100）
norm[pkg, t] = downloads[pkg, t] / downloads[pkg, base] × 100

# Step 2：AI SDK 子指数（等权重几何均值）
AI_SDK_sub[t] = ( norm[openai,  t]
               × norm[anthropic, t]
               × norm[google,    t] )^(1/3)

# Step 3：企业工具子指数（等权重几何均值）
Enterprise_sub[t] = ( norm[dd-trace,              t]
                    × norm[snowflake-sdk,          t]
                    × norm[@atlaskit/rovo-triggers, t] )^(1/3)

# Step 4：下载流量指数（flow 综合，几何加权幂次组合）
flow[t] = AI_SDK_sub[t]^0.6  ×  Enterprise_sub[t]^0.4      → enterprise_ai_download_flow_index

# B. 真实在产用量维度（usage）—— OpenRouter 全模型周度 token 成交量
# Step 5：真实用量指数 = 周成交量归一化后做 4 周移动平均（MA4 消除周度噪声）
usage[t] = MA4( total_tokens[t] / total_tokens[base] × 100 )   → enterprise_ai_real_usage_index

# C. 综合 EAPI = flow^β × usage^(1-β)，β=0.5（新增采用 与 真实用量 等权）
EAPI[t] = flow[t]^0.5  ×  usage[t]^0.5                        → enterprise_ai_penetration_index

# 采用几何均值而非算术均值：
#  — 几何均值对归一化比值做乘法等效于等比中项，对极端值有天然均值回归效应
#  — 避免被某一个包暴涨拉高综合指数失真

为什么需要 usage 维度？ Token 总消耗 = 已装机存量包 × 单应用调用频次 + 新增应用调用。 仅看下载量（flow）只能捕捉"新增"，当生态成熟、新增放缓但存量持续调用时，会系统性低估真实用量。 OpenRouter 作为模型网关，其周度 token 成交量直接反映真实在产消耗，天然涵盖存量贡献，是最佳 ground-truth。 其周度波动较大（同月内可翻倍/腰斩），故先做 4 周移动平均再并入。

真实支出指数（价格平减）

EAPI 综合指数（已含 flow + usage 两维度）反映企业 AI 的用量的增速。由于 token 价格指数持续下行， 仅看用量会高估企业的"实际开支"。真实支出指数引入价格代理 OPTI_VERCEL_OUTPUT （Vercel token 价格指数，日线，2026-07-10 起）对 EAPI 做平减，剥离价格因素， 得到更接近企业真实支出的口径。

编制公式
# Step 1：每周价格比（30 日 trailing 平滑）
#   对 EAPI 周窗内每一天 d 取 OPTI_VERCEL_OUTPUT 的前 30 日均值 trail(d)，
#   再对窗口内这些 trail(d) 取平均，得到周度价格；除以 07-10 锚点得 ratio。
#   采用 30 日 trailing 是为抑制代理日线的噪声与阶降（对比 7 日窗/居中 MA/14 日）。
price_ratio[t] = mean( trail30(OPTI_VERCEL_OUTPUT, d) for d in week ) / OPTI_VERCEL_OUTPUT(2026-07-10)

# Step 2：阻尼平减因子（α 为价格传导系数）
#  α=1.0 完全传导（硬平减，会夸大价格崩盘）
#  α=0.43 标定传导（已按 SDLLMTK 基准标定）→ 当前取值
#  α=0.0 无传导（真实支出 == 名义 EAPI）
price_deflator[t] = price_ratio[t]^α        (α = 0.43)

# Step 3：真实支出指数 = 名义 EAPI × 阻尼平减因子
RealSpend[t] = EAPI[t] × price_deflator[t]

# Step 4：4 周移动平均（平滑周度噪声）
RealSpend_MA4[t] = mean(RealSpend[t], RealSpend[t-1], RealSpend[t-2], RealSpend[t-3])

# Step 5：一阶导数（周环比差分，刻画支出动能与拐点）
RealSpend_MA4_deriv[t] = RealSpend_MA4[t] − RealSpend_MA4[t-1]

# 注：纯 log2 不改变结果(2^log2(r)=r，等价于 α=1)，"维持7月高位"的
#     杠杆是 α 而非 log2；α=0.43 已按 SDLLMTK 基准标定，末周真实支出≈169，贴近 SDLLMTK。

口径对比：名义 EAPI vs 真实支出指数

口径 2026-07-13 2026-09-14 期间变化
EAPI 综合指数（flow × usage 混合） 163.26 281.09 +72.2%
真实支出指数（α=0.43 · 30日trailing） 159.53 216.34 +35.6%

真实支出指数 09-14 为 216.34，较 7 月（159.53）提升约 36%： 名义下载量近乎翻倍，30 日 trailing 平滑后的 token 价格仍处下行，企业真实 AI 支出随用量增长而走高、并未同比例膨胀， 印证「支出维持高位」的判断。α=0.43 已按 SDLLMTK 基准标定；9-14→9-21 真实支出为 216.34→200.30（−7.4%，受 30 日 trailing 滞后与代理尾部下行的共同影响）。

⚠️ 口径说明：价格代理 OPTI_VERCEL_OUTPUT 是内部观测的 Vercel token 价格（日线，2026-07-10 起）， 并非 EAPI 内 npm 包（ai-sdk / dd-trace / snowflake-sdk）的真实合约价，且日线波动较大 （07-10 的 9.228 → 09-16 的 2.336，跌约 75%）。为抑制其噪声，周度价格比已采用 30 日 trailing 平滑（周窗内每日取前 30 日均值后再平均），但代理在 8 月中之后的 持续下行仍与已走平的 SDLLMTK 基准（W37 起 ~0.98）存在方向分叉。α=0.43 为标定传导系数： 通过对数比率回归使内部价格指数的乘性下行轨迹贴合 SDLLMTK Index（彭博 $/M tokens 基准，2026-02~09 周度）—— SDLLMTK 自 07-10 跌约 40%、内部指数自 07-10 跌约 67%，α = ln(0.60)/ln(0.33) ≈ 0.43。 结论的方向稳健，但绝对幅度为示意值；若后续能直接获取 SDLLMTK 最新值，建议直接替换该代理。
